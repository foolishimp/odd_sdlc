# T-204 Register Walk

Status: commentary, not ratified specification.

Current baseline: `d7dac6b T-204 tighten ABG-owned start proof`, 180 tracked
`build_tenants/typescript/code/src` files.

## Position

The remaining register debt is not "all registers are bad." T-204 deletes
product-local traversal/control truth. It preserves irreducible odd_sdlc
semantic carriers that ABG must consume as plugin I/O or product-domain
interpretation.

The current register surface splits into three buckets:

1. product semantic carriers that survive with positive ownership proof;
2. product read models/projections that may survive only over ABG-admitted
   runtime truth;
3. retired installed-operator/runtime carriers that must move to ABG or become
   non-authoritative compatibility projections.

## Current Defects

1. `SdlcEvaluateContentRegister` is the active migration surface. The design
   names `sdlc_evaluate_content_ledger` as authority; implementation now has a
   ledger replacement constant, purpose classification, and read-model catalog
   role for the legacy archive row, while prompts, analysis loaders, and
   archive fixtures still name
   `sdlc_evaluate_content_register`.

2. `operator/installed_operator.ts` no longer exports a local start executor at
   current HEAD, but it still constructs traversal consequences and writes
   runtime/consequence archive artifacts from product-local plugin-support code.
   That is the largest remaining ABG/product split.

3. `operator/traversal_consequence.ts` is mixed. It contains product-domain
   edge fulfillment, gain, residual-pressure, and closure interpretation, but
   also replay/action-binding mechanics that are close to ABG consequence
   ownership.

4. `analysis/carrier_loaders.ts` and workspace/gaps projections still rehydrate
   archive JSON directly. They may survive as diagnostics/read models only if
   they consume ABG-admitted projection truth or are labeled non-authoritative.

## Next Implementation Cuts

1. Migrate prompt text, analysis loaders, and archive fixtures from
   authority-register language to authority-ledger language. Keep legacy
   `*_content_register.json` only as projection wording where downstream
   archive compatibility requires it.

2. Split `installed_operator.ts` into product plugin/session code and ABG-owned
   consequence/archive output. The surviving odd_sdlc side should be plugin
   callbacks, prompt policy, carrier admission, and product interpretation.

3. Split `traversal_consequence.ts` into product-domain fold functions versus
   ABG-owned replay, transition, and consequence projection carriers.

4. Reprice `analysis/*` as either product diagnostics over ABG projection or
   `move_to_abg`. No archive loader should be closure authority.

5. Add drift guards:
   - reject tests that assert `sdlc_evaluate_content_ledger` is absent;
   - reject new installed-operator start/consequence authority carriers;
   - reject archive JSON scraping as gap/closure authority unless the source is
     explicitly ABG-admitted projection input.

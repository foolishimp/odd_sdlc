## Bug Fixed From This Run

The repeated component-depth repair had a concrete prompt-contract root cause. First-attempt worker prompts for component topology and realization schedule only instructed the worker to emit the row arrays; they did not pin the top-level fenced `component_depth_register` envelope or exact `registerVersion:"ts-component-depth-v1"`.

Patch:

- `build_tenants/typescript/code/src/operator/handoff.ts`
  - `componentDepthFieldSetForTarget` now uses exact envelope fields for every component-depth target: `kind=sdlc_component_depth_register`, `registerVersion=ts-component-depth-v1`, and `targetAssetType=<current target>`.
  - `compactComponentDepthDirective` now includes the fenced `json component_depth_register` carrier envelope on first-attempt prompts for topology, schedule, code, qualification, test, repair, and parity surfaces.
- `build_tenants/typescript/test_env/tests/test_t066_product_materialization_contract.test.mjs`
  - Added regression: `T-159 component-depth prompts pin the top-level register envelope on first attempt`.

Verification:

## Second Bug Fixed From This Run

The first `derive_component_code_surface` attempt spent 909 seconds and returned only `build.sbt`, `project/build.properties`, and `project/plugins.sbt`. The prompt already said product materialization was required and required role `source`, but when declared product file targets were empty it did not explicitly name the admitted component schedule as the source target set. That left too much room for the worker to treat build scaffolding as progress.

Patch:

- `build_tenants/typescript/code/src/operator/handoff.ts`
  - For full component-code surfaces, when declared product file targets are empty, the prompt now tells the worker to derive source targets from admitted topology/schedule authority and materialize files at `component_depth_register.componentRealizationRows[].relativePath`.
  - The prompt now states that build config files alone never satisfy required role `source` for `component_code_surface`.
- `build_tenants/typescript/test_env/tests/test_t066_product_materialization_contract.test.mjs`
  - The same T-159 prompt regression now covers `derive_component_code_surface`, including the schedule-derived source target guidance and build-config-only rejection wording.

Verification after the second patch:

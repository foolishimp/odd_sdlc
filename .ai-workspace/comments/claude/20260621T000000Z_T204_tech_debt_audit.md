## Q2 — Is execution through ABG?

**Yes — the command/control boundary is clean; zero confirmed local-authority violations.**
- No `bin`; package exports only `.`/`./install`/`./release`. The only `process.argv` in `code/src` (`operator/plugins/consequence/edge_projection.ts:1097`) is inside the worker-shard source-string template, not a launcher.
- Start is single-shot via ABG: `createOddSdlcAbgRuntimeBindingPlugins` (`abg_runtime_binding.ts:72`) calls `publicStartOnce` exactly once (`:90`); `publicStartOnce` (`public_start.ts:1715-1804`) returns a frozen outcome with no loop/advance. **`runEngine`/`runEngineIterate` is never called in `code/src`** — odd_sdlc never runs the engine. `advanceSdlcOperationalTransitionOnce` (`operational.ts:62`) sets `nextControlOwner:'abg_public_start'`.
- Enforced by gates: `test_t140` (no-local-forced-iteration) + `test_t203` (start steel thread) pass **21/21**; `test_t058:183-192`, `test_t197:626,632`, and `pack_no_command_artifacts.mjs:5-13` ban command artifacts from the built package.
- Harness conforms: every `test_env` traversal driver is an ABG `genesis-ts` spawn (`scenario_sandbox.mjs:260`, which refuses an odd_sdlc fallback at `:185-188`) or a single-shot call.

**One boundary item to resolve under T-159/T-205 (not a T-204 defect):** `operator/traversal_consequence.ts` locally derives a 5-term `edgeConverged` predicate (`:991-996`), folds the closure decision (`deriveSdlcEdgeClosureDecision :1054`), and projects next-action / action-binding (`constructSdlcNextActionProjection :1433`, `constructSdlcConsequenceTraversalActionBinding :1909`), with the runtime mirror in `installed_operator.ts:7341` (`deriveInstalledTraversalConsequence`) writing a consequence archive. This overlaps ABG's consequence-bind responsibility. It is **not** a local control loop (the no-iteration gates pass and the engine is never run here) — it is the SDLC-side **projection** of domain convergence/closure meaning. Whether the convergence predicate and closure fold are product-projected or ABG-owned is precisely the boundary that ABG **T-159** and odd_sdlc **T-205** are formalizing. Resolve it there; do not declare it clean-by-default and do not silently duplicate ABG's fold.

## Bottom line

T-204's collapse to "GTL program + product plugins + irreducible carriers" is **achieved on the control axis**: the command/control boundary is clean, start is single-shot via `publicStartOnce` (engine never run locally), and pack guards enforce it. **The dead-code story is much smaller than the first workflow pass claimed.** Production-only reachability mis-labeled the operator-subtree test API (`operator/index.ts` + `depth_traversal.ts` + `test_pipeline.ts`, consumed by 63 test files) as "dead," and mis-tagged `analysis/*` as `move_to_abg` against the live constitution — it is the product **closure-proof harness** bound by REQ-F-ODDSDLC-081 + ratified STAGED_COMPUTE_BOUNDARY + gates t197/t180, so it stays in-tenant (inventory tag corrected 2026-06-21). Genuinely free dead code was ~39 lines (`effects/{environment,index}.ts` deleted this pass; build + 66 gates green). The real remaining levers are: (1) ~11 low/medium DRY clusters into `shared/*` (two behavior-changing, several in in-flight T-205 consequence files — defer with the wave); (2) the `traversal_consequence.ts` edge-convergence/closure-fold ownership question, which belongs to ABG T-159 / odd_sdlc T-205. Net: the architecture is done, the "dead code" was largely a reachability artifact (test-facing + constitutionally-bound product surfaces), and what actually remains is opportunistic DRY plus one boundary question — not a large dead-code purge.

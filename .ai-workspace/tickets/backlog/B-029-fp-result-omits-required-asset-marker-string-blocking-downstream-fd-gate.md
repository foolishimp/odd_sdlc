## Observation

`derive_test_run_archive_surface` fails F_D check `test_run_archive_dependency_surfaces_present`
because `40-generated-test-modules.md` was produced by `derive_test_module_surface` without the
required marker string:

```
"This test module surface is regenerated by the bounded odd_sdlc constructor turn."
```

`workspace_assets.py:ASSET_MARKERS["test_module_surface"]` defines this as the required marker.
`_text_contains(marker_path, marker_text)` checks for it. The LLM produced a valid, well-structured
file that satisfies all semantic requirements but did not include this internal genesis contract string.

## Why It Happens

The marker string is an internal genesis certification mechanism. It is not mentioned in the
`[OUTPUT CONTRACT]` section of the manifest prompt. The LLM has no way to know it must be present.

## Consequence

- `derive_test_run_archive_surface` cannot proceed (dependency check fails)
- The pipeline stalls; a manual iterate is required
- Each such stall costs one extra F_P dispatch (~35 min, ~$0.21)

## Fix Direction (for requirements phase)

Requirement to add: "The manifest OUTPUT CONTRACT MUST include the required asset marker string
for every asset that has an entry in ASSET_MARKERS, with an explicit instruction that the LLM
must include it verbatim in the produced artifact."

Alternatively: the marker could be injected by the framework after F_P produces the result,
rather than relying on the LLM to include it. This would be a design decision.

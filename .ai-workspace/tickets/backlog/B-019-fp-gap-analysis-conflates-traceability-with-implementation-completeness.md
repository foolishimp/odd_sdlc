- intake: pipeline evaluation correctness / false convergence signal / silent feature failure

## Bug Statement

The `*_semantically_converged` F_P evaluators collapse two distinct concerns into
one pass/fail signal:

1. **Traceability** — the structural chain from intent through requirements,
   design, code, and tests is intact; requirement IDs are tagged at each
   surface.

2. **Completeness (gap analysis)** — each requirement's text and spirit is
   realized in the implementing code; behavioral contracts are present, not
   just structural stubs.

The current evaluators execute concern 1 only and call the result "semantic
convergence." Concern 2 is never evaluated.

A `sealed trait Foo {}` tagged `// Implements: REQ-LDM-001` satisfies
traceability if the tag is present. It does not satisfy completeness if
REQ-LDM-001 requires transitive composition with identity preservation.
The current pipeline cannot distinguish these two cases and emits
`delta = 0.0 — all evaluators pass` for both.

## Evidence

Observed in `data_mapper.test34` (genesis v3.1.0):

- 112 main Scala files generated, average **10.6 LOC per file** — all sealed
  traits, case class declarations, and type stubs.
- `code_surface_semantically_converged` F_P assessment passed with evidence:

  > "sealed trait hierarchies, trait contracts, and case class signatures are
  > faithful to the implementation design surface … all 71 live requirements
  > are traceable."

- The evaluator checked structural conformance to the module surface and
  requirement tag coverage. It did not read requirement text against
  implementation bodies.
- 18/18 edges reached `delta = 0.0`. Second run against the same workspace
  produced zero new events — the shallow state was locked in as complete.
- For comparison: `data_mapper.test32` (genesis v3.0.0, with triage pipeline)
  produced 59 files at avg **49.5 LOC**, 2,918 LOC total, 95.8% requirement
  coverage at depth.

## Root Cause

The `*_semantically_converged` evaluator prompts assess the current surface
against the prior surface for structural conformance. They do not:

- read requirement text
- evaluate whether implementation bodies exist and realize behavioral contracts
- distinguish a trait declaration from a method implementation
- reject a design surface that specifies only abstractions with no behavioral
  contracts

Because each surface was generated by v3.1.0 F_P workers that also produced
only structural abstractions, each evaluator found perfect conformance at every
stage. Shallowness propagated from design through module through code, and each
evaluator confirmed the current surface matched the previous. No divergence
was ever detected.

In genesis v3.0.0, the triage pipeline (observation → divergence → correction)
introduced external behavioral pressure that forced design surfaces to specify
implementation contracts. Without triage, v3.1.0 has no mechanism to surface
behavioral gaps — the evaluator hierarchy is the only gap detector, and it is
not evaluating behavior.

## Correct Evaluator Hierarchy

Three distinct layers are needed, and they must not be collapsed:

### Layer 1 — F_D fast filter (structural plumbing)
- Tag present (`// Implements: REQ-xxx`, `// Validates: REQ-xxx`)
- File exists, materialization kind matches
- REQ-ID appears in the traceability chain

This layer is an optimization gate, not evidence of completion. F_D cannot
assess behavioral realization.

### Layer 2 — F_P traceability backing
- Confirms the tag is meaningfully placed: the tagged file is the correct
  implementation site, not an incidental mention.
- Confirms the chain is semantically coherent, not merely structurally present.

### Layer 3 — F_P gap analysis (depth / completeness)
- For each live requirement: reads the requirement text and spirit.
- Reads the code claimed to implement it.
- Asks: does this code realize the behavioral contract stated in the
  requirement?
- A trait with no method bodies is not a realization of a functional
  requirement. A case class with no logic is not a realization of a processing
  requirement.
- This layer must reject structural stubs as incomplete regardless of tag
  coverage.

A requirement is complete when the implementation realizes its **text and
spirit**, not when it carries its ID tag.

## Impact

- The convergence signal (`delta = 0.0`) is false when shallow stubs are
  present. The pipeline reports completion for work that is not done.
- No human is alerted. The workspace appears fully converged and ready for
  release.
- A second run cannot recover depth because delta = 0.0 provides no pressure
  surface; all evaluators pass immediately on re-entry.
- The pipeline's core promise — requirements realized in code, traceable from
  intent to test — is silently broken. Traceability is present; realization
  is absent.

## Required Fix

1. Reprice the `*_semantically_converged` evaluator contract to make layer 3
   (behavioral realization) explicit and mandatory.
2. The evaluator prompt must include the requirement text as a primary input,
   not just the structural surface match.
3. A surface containing only trait declarations, case class signatures, or
   type aliases with no method bodies must not pass `semantically_converged`
   for requirements specifying behavioral contracts.
4. The triage pipeline absence in v3.1.0 must be compensated by stronger
   in-evaluator depth checks, or the triage pipeline must be restored.
5. Add a specific F_D check (or F_P check backed by F_D) that counts
   non-trivial implementation bodies (methods with logic, not just
   declarations) per requirement and gates convergence on a minimum threshold.

## Acceptance

- A workspace containing only sealed traits and case class stubs cannot reach
  `delta = 0.0` on the code surface edge.
- Re-running on a shallow workspace opens behavioral gaps, not zero gaps.
- The evaluator evidence for `code_surface_semantically_converged` references
  requirement text and behavioral realization, not structural conformance alone.
- test34 re-run with the corrected evaluators surfaces implementation gaps
  and drives F_P construction toward substantive bodies.

## Notes

This bug is distinct from the marker-omission regression in v3.1.0 (missing
genesis provenance marker text in generated surfaces), which was separately
worked around by manual injection. That regression is a different F_D gap.

This bug is about the core semantic convergence contract. It applies to any
version of the pipeline that does not enforce layer 3 gap analysis.

The clearest diagnostic is the LOC-per-file metric: when average main file LOC
is below a threshold consistent with behavioral implementation (rough lower
bound: ~30 LOC for non-trivial Scala), the code surface is structurally present
but behaviorally empty, and the pipeline should not converge.

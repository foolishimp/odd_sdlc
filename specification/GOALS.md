# odd_method Goals

State the current overriding concerns for `odd_method` in present tense.

## Position

Goals focus one bounded wave of work.

They are narrower than product definition and shorter-lived than intent.

They keep the current repricing and bootstrap work oriented without turning
temporary focus into accidental constitutional law.

## Current Goals

- reprice `odd_sdlc` from the current first-slice tenant into the generic
  software-domain package on the `odd_method` line
- define the software-domain model around a governed SDLC worksite lifecycle:
  request, gate, specify, design, implement, qualify, release, deploy,
  observe, return, retrofit, and relaunch
- expand the live asset ontology beyond the bootstrap toy so the domain can
  govern request, implementation, qualification, release, deployment,
  runtime-return, and maintenance work
- define first-class software work acts such as `generated`, `adopted`,
  `imported`, `repaired`, `retrofitted`, `released`, `deployed`, and
  `returned` through explicit provenance rather than ambient file state
- make configured `F_P` the normal supervisory transform for generic
  software-domain edge traversal under explicit edge contracts
- build layered `F_D` authority around that work:
  universal `Core F_D`, optional `Capability F_D`, mandatory `Postflight F_D`,
  and `Operational F_D` over returned evidence
- replace placeholder implementation, release, and archive assumptions in the
  current first-slice tenant with governed target binding and evidence truth
- keep GTL and ABG small, declarative, fail-closed, and overrideable while
  keeping software-domain semantics in `odd_sdlc`
- treat runtime-returned evidence as a first-class governed input to further
  SDLC work rather than as external noise
- convert the `data_mapper.test19` process failure into a standing
  anti-regression boundary for the domain package
- keep `odd_service` subordinate to ABG runtime truth and `odd_sdlc` domain law
  as the orchestration line continues to incubate
